# Сборка и прошивка

Вы собираете прошивку в Visual Studio с плагином VisualGDB и прошиваете ESP32 по кабелю USB. На
этой странице описаны шаги для прошивки {{ app_version }}.

---

## Требования

| Компонент | Версия |
|-----|--------|
| Visual Studio | 2022 Community с VisualGDB 5.6 |
| Ядро Arduino | `esp32` **2.0.11** |
| Плата | ESP32 Dev Module, основная плата Ver 1.1 |

!!! warning "Используйте только ядро 2.0.11"
    В ядре 3.x нет имён событий WiFi, которые использует прошивка, а его библиотеки не совпадают с
    теми, что лежат в папке `Libs`. Сборка завершается ошибкой. Другие версии 2.0.x не проверялись.

---

## Установите ядро

1. В Visual Studio откройте **«Tools → VisualGDB → Manage VisualGDB Packages»**.
2. Отметьте **«Show old packages»**. Иначе Visual Studio скрывает версию 2.0.11.
3. Выберите пакет **esp32** версии 2.0.11 и установите его.

---

## Получите исходники

1. Клонируйте репозиторий вместе с подмодулями `Libs/NTPClient`, `Libs/WebSerial` и `Libs/NeoPixelBus`. В Visual Studio
   нет команды для подмодулей; в терминале выполните `git clone --recurse-submodules` с адресом
   репозитория или `git submodule update --init --recursive` в уже клонированной копии.
2. Откройте `Software/Software_ver_2/HAQuDA_Esp32/HAQuDA_Esp32.sln` в Visual Studio.

---

## Задайте переменные сборки

Прошивка берёт четыре текста из переменных сборки. В исходниках их намеренно нет.

| Переменная | Назначение |
|------------|----------|
| `AP_ssid_uv` | Имя точки доступа лампы. Имя хоста лампы в вашей сети фиксированное: `haquda`. |
| `AP_pass_uv` | Пароль точки доступа, от 8 до 63 символов. |
| `DDNS_Domain_uv` | Домен DuckDNS. <span class="wip">WIP</span> |
| `DDNS_Token_uv` | Токен DuckDNS. <span class="wip">WIP</span> |

1. Откройте свойства проекта VisualGDB для `HAQuDA_Esp32` (**«Project → VisualGDB Project
   Properties»**).
2. Задайте четыре пользовательские переменные.

VisualGDB сохраняет ваши значения в файле `HAQuDA_Esp32.vgdbproj.<user>.user`, который Git
игнорирует. Никогда не фиксируйте в репозитории реальные значения.

!!! note "WIP"
    Обновления DuckDNS не готовы: лампа их не отправляет. Для сборки оба значения всё равно нужны.

---

## Соберите прошивку

1. На панели инструментов выберите конфигурацию **«Debug»** и платформу **«ESP32_Dev_Module»**.
2. Выберите **«Build → Build Solution»**.
3. Результат лежит в `Software/Software_ver_2/HAQuDA_Esp32/Output/ESP32_Dev_Module/Debug`.

---

## Прошейте лампу

Подключите лампу к компьютеру кабелем USB. На основной плате стоит преобразователь USB–UART
FT232RL.

| Способ | Шаги |
|--------|------|
| UART | Выберите **«Debug → Program and Start Without Debugging»**. По умолчанию VisualGDB использует порт `COM8`; если у вас другой, выберите свой порт в свойствах проекта. Микросхема сама переводит ESP32 в режим загрузчика. |
| JTAG с OpenOCD | Подключите J-Link к разъёму JTAG и выберите **«Debug → Start Debugging with GDB»**. |

### Проверьте версию

Откройте терминал последовательного порта лампы на скорости 115200 бод, 8N1, и перезапустите
лампу. Сначала загрузчик ESP32 печатает свои строки. Строка `HAQuDA firmware v{{ app_version }}`
идёт после них.

Прошивка раскрашивает уровни лога кодами ANSI. Терминал, который их не понимает, показывает коды
как лишние символы вроде `[0;32m` перед строками; используйте терминал Visual Studio или монитор
из следующего раздела: в них уровни видны цветом.

## Сборка и прошивка из VS Code

Вместо Visual Studio можно собирать основную копию репозитория или любое её рабочее дерево из
одного окна VS Code и прошивать лампу по UART. Все сборки используют один кэш сборки в папке
`.bench` основной копии. Из выбранной папки берётся только папка `sketches`, всё остальное — из
основной копии.

### Настройка (один раз)

1. Настройте сборку в Visual Studio в основной копии, как описано выше: VisualGDB, ядро и
   переменные сборки.
2. Установите Python 3 и выполните `py -3 -m pip install esp-idf-monitor`.
3. В VS Code запустите задачу **«HAQuDA: Install picker»** (**«Terminal → Run Task...»**), затем
   выполните **«Developer: Reload Window»**. После установки диалог сам предложит
   **«Reload Window»**.

Если выбор папки устарел, задачи со всплывающим окном не запускаются, а диалог предлагает
установить его заново. Запустите **«HAQuDA: Install picker»** и перезагрузите окно.

### Каждый раз

1. Нажмите **Ctrl+Shift+B** и выберите папку во всплывающем окне.
2. Пока идёт сборка, сами переведите ESP32 в режим загрузчика (удерживайте BOOT, нажмите reset),
   если у лампы нет автоматического сброса.
3. Лампа прошита, рядом со сборкой открывается монитор последовательного порта. Монитор печатает
   метки времени. Выйти из него можно по **Ctrl+]** или **Ctrl+C**. Меню **Ctrl+T** монитора в
   терминале VS Code не работает.

### Задачи

Остальные задачи запускаются через **«Terminal → Run Task...»**.

| Задача | Что делает |
|--------|------------|
| HAQuDA: Build + Flash + Monitor | Спрашивает папку, собирает, прошивает и запускает монитор. Это задача для **Ctrl+Shift+B**. |
| HAQuDA: Build + Flash | Спрашивает папку, собирает и прошивает. Работающий монитор освобождает порт для прошивки. |
| HAQuDA: Build | Спрашивает папку и только собирает. |
| HAQuDA: Flash | Прошивает последнюю сборку без пересборки. |
| HAQuDA: Monitor | Запускает только монитор последовательного порта. |
| HAQuDA: Change COM port | Спрашивает COM-порт и запоминает его для прошивки и монитора. |
| HAQuDA: Install picker | Устанавливает расширение, которое показывает всплывающие окна. |
| HAQuDA: Remove bench | Просит подтверждение и безопасно удаляет `.bench`. Следующая сборка будет полной. |

Одновременно идёт только одна сборка. Пока она идёт, вторая сборка, **«HAQuDA: Flash»**,
**«HAQuDA: Change COM port»** и **«HAQuDA: Remove bench»** завершаются с ошибкой; запустите их
снова, когда сборка закончится. Сборка тоже завершается с ошибкой, пока идёт прошивка.

!!! warning "Не передавайте `.bench` и не удаляйте её вручную"
    Журнал сборки в `.bench` и ссылка внутри неё содержат ваши секретные переменные сборки,
    поэтому не передавайте папку другим. Чтобы удалить её, запустите **«HAQuDA: Remove bench»**.
    В ней лежат junction-ссылки на настоящие папки с исходниками, и при удалении вручную их можно
    потерять.

## Сборки из GitHub Actions

GitHub Actions собирает прошивку при каждом push и pull request, которые меняют папку прошивки.
Эта сборка только проверяет, что прошивка компилируется. Используется то же ядро 2.0.11, что и в
локальной сборке. Артефакт `HAQuDA_esp32_esp32_esp32` содержит папку сборки arduino-cli: образ
прошивки, загрузчик, таблицу разделов и файл `.elf`.

Рабочий процесс подставляет в переменные сборки фиктивные значения: имя точки доступа
`actions_ssid`, пароль `actions_pass` и ненастоящие значения DuckDNS. Не прошивайте артефакт в
лампу, которой пользуетесь. Соберите прошивку сами со своими значениями и прошейте её, как
описано выше.

### Модульные тесты

В репозитории есть модульные тесты для ПК в проекте `HAQuDA_Tests` того же решения. В Visual
Studio выберите **«Build → Build Solution»**, затем откройте **«Test → Test Explorer»** и нажмите
**«Run All Tests»**. Они проверяют логику прошивки на компьютере, а не на лампе. GitHub Actions тоже запускает их в
проверке «Host tests / Test», и упавший тест делает проверку красной.
